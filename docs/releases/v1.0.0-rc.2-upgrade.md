# Upgrade to Cortrix v1.0.0-rc.2

RC2 is a new prerelease. Do not move, overwrite, or retarget the immutable `v1.0.0-rc.1` tag. Back up persistent data and validate the exact RC2 candidate against a copy before changing an existing environment.

## Before Upgrading

- Read the current [compatibility matrix](../compatibility.md), especially the blocked auth, tenant, RBAC, memory-extraction, logging, and production-readiness areas.
- Record the existing source revision, configuration, model assets, database path, and rollback procedure.
- Re-run API, SDK, MCP, deployment, and persistence smoke tests against the exact RC2 tag in an isolated environment.
- Keep source documents authoritative until indexing, query behavior, deletion, and rollback have been verified for the target deployment.

## Task Lifecycle and Persistent Data

RC2 includes substantial asynchronous task-lifecycle and managed-input safety work. Verify task submission, terminal states, resubmission, cancellation races, managed-input cleanup, cleanup scheduling after restart, namespace-scoped task identity, and repeated or same-content batch uploads.

No new manually applied SQL migration file appears between `v1.0.0-rc.1` and this candidate. Runtime startup still creates or adjusts indexes and task-state behavior, so this observation is not a substitute for a backup or an upgrade test against a copy.

## Query and Reranking

- Use per-request `rerank=false` when a relevance cross-encoder is unsuitable for the workload.
- Do not rely on the namespace-level reranker enable setting to disable reranking in the live query path.
- HyPE-derived results preserve source-document identity in the current query path.

## MCP

- The local MCP server supports modern SDK v2 stdio discovery and the legacy initialization path.
- Session and trace identity are propagated to Cortrix Server.
- Verify client/server API compatibility before replacing an existing MCP environment. Local stdio remains the public transport boundary.

## Deployment

- Docker Compose remains loopback-only by default.
- Publishing to a LAN address is an explicit opt-in for isolated test networks; it is not evidence of internet-facing production readiness.
- Re-run the source-backed readiness and reranked-query checks from the [Quick Start](../QUICKSTART.md).

## Benchmark Interpretation

- Use the immutable [four-corpus CPU bundle](https://github.com/cortrix/cortrix-benchmarks/tree/4b94390c1d5f7be95065e7483362ec7f93774ed7/results/published/beir-four-corpus-cpu-2026-08-v1) for the RC2 retrieval evidence.
- Do not compare the Quora 2,000-query subset with a full-query-set result.
- Do not interpret published CPU latency as concurrent production capacity.
- Do not infer answer quality, security, compliance, competitive rank, or business impact from retrieval metrics.

## Rollback

Stop the RC2 environment, restore the recorded RC1 configuration and data backup, and check out the immutable `v1.0.0-rc.1` tag. Do not reuse a database that RC2 has opened unless the rollback test demonstrates compatibility for that exact copy.
