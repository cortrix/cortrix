# Cortrix v1.0.0-rc.2 Release Notes

Cortrix `v1.0.0-rc.2` is a prerelease for local evaluation and integration testing. It is not a production-readiness claim. Review the [compatibility matrix](../compatibility.md) and [upgrade notes](v1.0.0-rc.2-upgrade.md) before moving an RC1 environment forward.

Cortrix feature identifiers such as `F42`, `F02`, and `P12` resolve through the public [Feature Index](../feature-index.md). Each change below links to its public Issue or pull request for reviewable implementation detail.

## Highlights

- Cortrix-authored material in RC2 is available under the Apache License 2.0. The historical `v1.0.0-rc.1` release remains under `AGPL-3.0-only`, and third-party material retains its identified license.
- Asynchronous ingestion and managed-input handling now include stronger namespace-scoped task identity, terminal-state transitions, cancellation-race coverage, cleanup scheduling, and retry deduplication.
- Query callers can set `rerank=false` for duplicate-detection and similar-item workloads where a relevance cross-encoder may be unsuitable.
- The local MCP server supports the modern SDK v2 stdio discovery path while retaining legacy initialization compatibility, and it propagates session and trace identity to Cortrix Server.
- Parser output handling, sparse-vector decoding, configuration validation, memory-scope validation, operation-log error reporting, and GC CLI validation are hardened.
- Docker Compose remains loopback-only by default, with an explicit publish-address opt-in for isolated test networks.

## FiQA Retrieval Accuracy

This is a cross-round observation for the non-LLM cross-encoder reranking configuration. It is not a comparison between the July and RC2 configurations labeled `Full Stack`.

The RC2 benchmark results show higher retrieval accuracy on FiQA than the July baseline: nDCG@10 increases from 0.2526 to 0.3125 (+23.7%), and Recall@10 increases from 0.3635 to 0.4523 (+24.4%).

| Metric | July cross-encoder result | August cross-encoder result | Relative change |
| --- | ---: | ---: | ---: |
| nDCG@10 | 0.2526 | 0.3125 | +23.7% |
| Recall@10 | 0.3635 | 0.4523 | +24.4% |

These are measured retrieval-accuracy results, not server performance measurements. The compared runs also differ in build, configuration, and execution environment, so this comparison does not isolate the improvement to a single code change.

Core [PR #82](https://github.com/cortrix/cortrix/pull/82) and its merged public documentation pin the evidence identities, query scope, and interpretation limits used below. The complete evidence is preserved in the Cortrix Benchmarks [four-corpus CPU bundle](https://github.com/cortrix/cortrix-benchmarks/tree/4b94390c1d5f7be95065e7483362ec7f93774ed7/results/published/beir-four-corpus-cpu-2026-08-v1):

- measured Core: [`79a4eb17c62521338d1ac47a9749e6230e87e69b`](https://github.com/cortrix/cortrix/commit/79a4eb17c62521338d1ac47a9749e6230e87e69b);
- public runner: [`9490520c24a96ed97b80073ed3ebab096b80550b`](https://github.com/cortrix/cortrix-benchmarks/commit/9490520c24a96ed97b80073ed3ebab096b80550b);
- immutable bundle commit: [`4b94390c1d5f7be95065e7483362ec7f93774ed7`](https://github.com/cortrix/cortrix-benchmarks/commit/4b94390c1d5f7be95065e7483362ec7f93774ed7).

The bundle contains 16 measured retrieval configurations across SciFact, NFCorpus, FiQA, and Quora. SciFact, NFCorpus, and FiQA use every judged test query; Quora uses the full 522,931-document corpus and the first 2,000 of 10,000 judged queries. It measures retrieval quality at `top_k=10`; it does not establish answer quality, concurrent production latency or capacity, security or compliance, competitive ranking, or business outcomes. Comparisons across independently ingested namespaces carry the variation disclosed in the bundle; only the Quora arms use shared namespaces.

The coordinated evidence identity for this prerelease is `cortrix-v1.0.0-rc.2-evidence-v1` in [Cortrix Benchmarks](https://github.com/cortrix/cortrix-benchmarks/releases/tag/cortrix-v1.0.0-rc.2-evidence-v1). ## Changes by Area

The list below covers public changes since `v1.0.0-rc.1`. Feature identifiers describe the affected public capability; Issue and PR links are the reviewable implementation record.

### Storage and asynchronous ingestion

- **`F42` — namespace-scoped task identity and managed-input ownership.** Batch materialization no longer derives file identity from caller-controlled document IDs, and terminal, cancellation, restart, and resubmission paths have explicit ownership rules. [PR #31](https://github.com/cortrix/cortrix/pull/31) supersedes [PR #30](https://github.com/cortrix/cortrix/pull/30).
- **`F42` — retention and terminal-state correctness.** Production now constructs the task cleanup scheduler, and terminal transitions are guarded by their expected prior state. [Issue #34](https://github.com/cortrix/cortrix/issues/34), [PR #49](https://github.com/cortrix/cortrix/pull/49), [Issue #57](https://github.com/cortrix/cortrix/issues/57), [PR #59](https://github.com/cortrix/cortrix/pull/59).
- **`F42` — deep-queue dispatch and managed-input release scalability.** Composite and partial indexes remove queue-wide work from the task-manager critical path. [Issue #72](https://github.com/cortrix/cortrix/issues/72), [PR #76](https://github.com/cortrix/cortrix/pull/76), [Issue #74](https://github.com/cortrix/cortrix/issues/74), [PR #77](https://github.com/cortrix/cortrix/pull/77).
- **`F03` / `F42` — queue configuration and enrichment backfill safety.** Invalid `spc.max_queue_size` values are rejected, and enrichment sweeps avoid enqueueing work already active for the same document. [PR #50](https://github.com/cortrix/cortrix/pull/50), [PR #63](https://github.com/cortrix/cortrix/pull/63).
- **Storage initialization.** SQLite auto-vacuum configuration is applied before the database file is initialized. [PR #56](https://github.com/cortrix/cortrix/pull/56).

### Retrieval, parsing, memory, and observability

- **`F02` — workload-aware reranking guidance and verified opt-out.** Per-request `rerank=false` is pinned through the execution path for duplicate-detection and similar-item workloads; public benchmark guidance now matches the current evidence. [Issue #75](https://github.com/cortrix/cortrix/issues/75), [PR #79](https://github.com/cortrix/cortrix/pull/79), [Issue #80](https://github.com/cortrix/cortrix/issues/80), [PR #82](https://github.com/cortrix/cortrix/pull/82).
- **`F38` — HyPE source identity.** Public query results preserve the originating document identity for HyPE-derived matches. [Issue #68](https://github.com/cortrix/cortrix/issues/68), [PR #70](https://github.com/cortrix/cortrix/pull/70).
- **`F40` — sparse-vector corruption handling.** Oversized sparse-vector blobs are rejected as corruption instead of being decoded unsafely. [PR #54](https://github.com/cortrix/cortrix/pull/54).
- **`F06` — parser bridge output contract.** Python parser bridges reserve stdout for their JSON envelope so dependency output cannot corrupt the protocol. [PR #61](https://github.com/cortrix/cortrix/pull/61).
- **`MEM02` — contradiction response parsing.** JSON returned inside Markdown code fences is unwrapped before contradiction-judge parsing. [PR #51](https://github.com/cortrix/cortrix/pull/51).
- **`MEM03` / `MEM05` — memory search scope validation.** Unknown scope values now fail with HTTP 400 instead of silently selecting an unintended path. [PR #55](https://github.com/cortrix/cortrix/pull/55).
- **`F18a` and server operations.** Operation-log cleanup records statement-preparation failures, and a dangling GC CLI `--config` flag is treated as a usage error. [PR #52](https://github.com/cortrix/cortrix/pull/52), [PR #53](https://github.com/cortrix/cortrix/pull/53).

### MCP and agent-facing setup

- **`P12` / `F13` — traceable MCP calls.** MCP transport propagates session, trace, and agent identity to Cortrix Server. [Issue #25](https://github.com/cortrix/cortrix/issues/25), [PR #26](https://github.com/cortrix/cortrix/pull/26).
- **`P12` — modern and legacy client compatibility.** The local stdio server supports SDK v2 discovery while retaining the legacy initialization path, and it publishes a useful server version. [PR #27](https://github.com/cortrix/cortrix/pull/27), [PR #29](https://github.com/cortrix/cortrix/pull/29).
- **Agent-assisted local setup.** The documentation includes a local setup path written for coding agents. [PR #24](https://github.com/cortrix/cortrix/pull/24).

### Deployment, Web UI, security, and licensing

- **`F24` — explicit LAN publishing.** Docker Compose remains loopback-only by default and accepts an explicit publish-address override for isolated evaluation networks. [PR #60](https://github.com/cortrix/cortrix/pull/60).
- **`P02a` — production Web dependencies.** `dompurify`, `react-router`, and `react-router-dom` are updated on the production dependency surface. [PR #83](https://github.com/cortrix/cortrix/pull/83).
- **License boundary.** Current Cortrix-authored RC2 material moves to Apache-2.0 while the immutable RC1 release and third-party materials retain their existing terms. [PR #84](https://github.com/cortrix/cortrix/pull/84).

### Test and continuous-integration quality

- **`F23` — lower-cost PR feedback without dropping required coverage.** The PR lane fixes ccache use, removes duplicate or record-only work, introduces an executable change classifier and aggregate `pr-gate`, and routes documentation-only changes away from heavy jobs. [PR #28](https://github.com/cortrix/cortrix/pull/28), [PR #46](https://github.com/cortrix/cortrix/pull/46), [PR #48](https://github.com/cortrix/cortrix/pull/48).
- **`GEN-Agent` / `F23` — honest explain-path tests.** Explain blocks use one serializer, and tests assert serializer-backed behavior instead of reproducing a second implementation. [PR #44](https://github.com/cortrix/cortrix/pull/44), [PR #45](https://github.com/cortrix/cortrix/pull/45).
- **`F23` — assertion audit.** Twenty-six tautological or self-asserting tests were replaced with behavior-sensitive assertions. [Issue #32](https://github.com/cortrix/cortrix/issues/32), [PR #58](https://github.com/cortrix/cortrix/pull/58).

### Documentation and repository governance

- The README now includes the public Cortrix architecture and an agent-oriented path into the repository. [PR #23](https://github.com/cortrix/cortrix/pull/23).
- The public, versioned Feature Index explains the `F##`, `MEM##`, `P##`, `D0`–`D6`, `TD-*`, and `GEN-*` vocabulary used by source, tests, configuration, and errors. [PR #43](https://github.com/cortrix/cortrix/pull/43).
- Branch lifetime, protected `main`, the `release/1.0` line, and RC maintenance rules are now documented. [Issue #81](https://github.com/cortrix/cortrix/issues/81), [PR #85](https://github.com/cortrix/cortrix/pull/85).

## Compatibility Notes

- `rerank=false` on an individual query is the verified rerank opt-out. The namespace-level `reranker_config.enabled` setting is not wired into the live query path ([Issue #75](https://github.com/cortrix/cortrix/issues/75)).
- Missing query text and failed requests are accounted for separately by the public benchmark runner.
- Local stdio is the current public MCP transport boundary; verify the target API contract before changing an existing client environment.
- Auth login, tenant/member/ACL/quota conformance, RBAC and tenant-isolation denial matrices, MEM02 extraction, and default log redaction remain blocked or verification-required as described in the [compatibility matrix](../compatibility.md).

## Known Issues and Follow-up Work

- Enrichment backfill still has open producer-independent scheduling and transport-retry follow-ups. [Issue #62](https://github.com/cortrix/cortrix/issues/62), [Issue #78](https://github.com/cortrix/cortrix/issues/78).
- HyPE LLM-call metrics are not yet connected to the production enrichment path. [Issue #69](https://github.com/cortrix/cortrix/issues/69).
- The LAN publish-address option does not yet provide a complete authenticated setup path without manual configuration. [Issue #71](https://github.com/cortrix/cortrix/issues/71).
- Single-namespace P-HNSW ingestion remains constrained by serialized durability and index mutation work. [Issue #73](https://github.com/cortrix/cortrix/issues/73).
- Cross-encoder reranking remains default-on even for workloads where the verified per-request opt-out is preferable. [Issue #75](https://github.com/cortrix/cortrix/issues/75).

## Release Evidence

Release evidence requires an overall successful full-scope run on the exact candidate commit; a generated artifact alone does not establish that the release gate passed.

The release gate must run against the exact candidate commit with `release_tag=v1.0.0-rc.2`, `validation_scope=full`, and a matching 40-character `source_revision`. Its hard evidence includes:

- version and source identity;
- Stage 2 tests and cross-platform Web end-to-end tests;
- Community Edition isolation checks;
- loopback Quick Start and network-none reuse;
- external-address negative controls;
- Trivy with no HIGH or CRITICAL image findings;
- SPDX and CycloneDX SBOMs;
- Lighthouse and pinned model integrity checks.

GitHub automatically provides source archive links for the tag. The release gate produces the Actions artifact `sbom-v1.0.0-rc.2`, containing `sbom.spdx.json`, `sbom.cdx.json`, `trivy.json`, and negative-control logs. RC2 does not promise a separately published container image or prebuilt binary unless the GitHub prerelease explicitly attaches one.
