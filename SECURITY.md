# Security Policy

## Supported versions

Before the first public release, security support applies to the latest commit on the default branch only. Other branches, tags, releases, and older commits are not supported. This policy will be replaced with an explicit supported-version table before the first release.

## Reporting a vulnerability

Report suspected vulnerabilities privately to [security@cortrix.ai](mailto:security@cortrix.ai). Do not open a public issue for an unpatched vulnerability, credentials, customer data, or exploitable private infrastructure details.

The Cortrix Security Response Team will acknowledge receipt within 5 business days. An acknowledgement confirms intake and initial routing; it is not a promise that triage, remediation, or a release will finish within that window.

Include the affected 40-character commit, impact, minimal reproduction, and sanitized evidence. Do not include secrets unless the response team explicitly requests a secure transfer method.

## Coordinated disclosure

Do not disclose the vulnerability publicly before a fix is available or a mutually agreed disclosure date is reached. The response team will coordinate severity assessment, remediation status, and disclosure timing with the reporter.
